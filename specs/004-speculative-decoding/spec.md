## 背景：基于 001/002/003 的基线与本次变更范围

本特性是对 `specs/001-floating-ime-converter`（浮窗转换器 MVP）、`specs/002-lattice-dict-model-switch`（真实词库 + Lattice 多候选 + 本地模型可切换）、`specs/003-model-tier-perf-tuning`（模型档位调整、GBNF 语法约束解码与防抖节奏优化）三项已交付特性的后续性能优化专项，而非从零开始的新系统。以下既有契约继续作为本特性基线，除非本 spec 后续条款明确声明取代：

- 001 FR-004/FR-005、SC-003：慢流防抖触发、生成状态迁移（`Idle → Debouncing → Generating → Ready/Stale`），以及"首批内容延迟 < 300 毫秒、整句生成延迟 < 800 毫秒"的性能阈值定义。
- 002 Clarifications（2026-10-19 对 001 SC-003 的交叉修订）：SC-003 的延迟阈值**仅对低配默认模型强制适用**；用户主动切换为中/高配模型视为已知情地以更长延迟换取更高翻译质量，MUST NOT 要求中/高配模型满足该阈值。
- 003 FR-001/FR-002：中配推荐模型为 Qwen2.5-7B-Instruct、高配推荐模型为 Qwen2.5-14B-Instruct（取代 002 原 14B/32B 数值）；三档推荐结构、本地模型目录扫描/切换/回退机制（002 FR-009～FR-015）不变。
- 003 FR-005～FR-009：`LlmEngine::generate()` 已引入 GBNF 语法约束采样，对外签名（输入输出均为 `QString`）与 QML↔C++ 会话契约（`contracts/qml-cpp-session-interface.md`）保持不变；该约束为推理管线内部实现细节。
- 003"方向二：投机解码——已识别但本特性不实施的改进方向"小节：已记录投机解码的背景、预期收益与工程复杂度评估，明确"本特性不实施该方向，留待后续单独立项的专项 spec 评估与交付"。**本 spec 即是该后续专项**。

本 spec **不取代**上述任何既有条款的文字本身；本特性的交付范围是在既有单模型自回归推理管线基础上，**新增**草稿模型辅助的投机解码能力，使中/高配档位用户在不改变既有模型档位结构、不改变延迟阈值定义文字、不改变 QML↔C++ 契约的前提下，获得可测量的生成延迟降低。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 中配/高配档位用户在不牺牲翻译质量前提下获得更快的生成速度 (Priority: P1)

用户此前在设置页面将慢流模型切换为中配（Qwen2.5-7B-Instruct）或高配（Qwen2.5-14B-Instruct）档位，以换取比低配默认模型更高的翻译语义质量；003 已将这两档的推荐型号调整为延迟代价更低的数值，但目标模型逐 token 自回归生成的基本推理方式未变，延迟仍明显高于低配默认档位。本特性交付后，用户在选用中配或高配模型时，系统在后台使用一个更小的草稿模型辅助目标模型加速生成，用户感知到的整句生成延迟相较不启用投机解码时有可测量的降低，而最终呈现在预览区、供用户确认上屏的翻译文本内容与质量相较不启用投机解码时没有差异——用户无需在"更快"和"更准"之间做任何新的取舍。

**Why this priority**：这是本特性唯一的核心交付价值——"让中/高配用户更快地获得与此前相同质量的结果"，所有其他用户故事（草稿模型获取、未配置时的行为、搭配关系呈现）都是围绕这一核心价值的支撑性场景，故列为最高优先级。

**Independent Test**：在设置页面切换为中配或高配模型，并在已正确配置可用草稿模型的前提下，使用同一测试样例分别执行"启用投机解码"与"不启用投机解码（即当前 003 已交付的既有单模型生成路径）"两种路径的生成，比较二者的整句生成延迟与生成文本内容，验证延迟有可测量的降低、生成文本内容在语义上无差异。

**Acceptance Scenarios**:

1. **Given** 用户已将模型档位切换为中配或高配，且该档位已按本特性要求正确配置可用的草稿模型，**When** 用户输入一段草稿文本触发慢流生成，**Then** 系统使用投机解码路径完成生成，整句生成延迟相较同一测试样例在不启用投机解码时的既有延迟有可测量的降低。
2. **Given** 投机解码路径与既有单模型生成路径分别对同一输入执行生成，**When** 比较两次生成得到的最终标准中文文本，**Then** 两者在语义上一致，用户确认上屏的内容不因投机解码的引入而发生可感知的质量下降。
3. **Given** 用户已将模型档位切换回低配默认档位，**When** 用户继续输入触发慢流生成，**Then** 系统行为与 001/002/003 已确立的既有低配生成路径一致，不受本特性影响（低配默认档位 MUST NOT 启用投机解码，见 FR-005，2026-10-20 澄清）。

---

### User Story 2 - 用户了解草稿模型的获取与配置方式 (Priority: P2)

投机解码需要额外的草稿模型文件才能生效。用户在设置页面查看模型相关信息时，能够了解当前所选目标模型档位是否需要、以及如何获取对应的草稿模型，而不是在没有任何说明的情况下疑惑"为什么开启了某个选项却没有变快"。

**Why this priority**：这是让 User Story 1 的核心价值对用户可发现、可操作的必要前提，但本身不直接产生加速效果，故列为次优先级。

**Independent Test**：在设置页面查看中配/高配档位的模型信息展示区域，验证其中包含与草稿模型获取/配置相关的说明性信息，涵盖推荐候选规格（FR-004：Qwen2.5-0.5B-Instruct / Qwen2.5-1.5B-Instruct）、自动搭配关系说明（FR-007：按目标模型档位自动固定搭配，用户无需手动选择）以及未配置时的提示文案（FR-006）；具体 UI 呈现细节留待 `/speckit.plan` 阶段设计。

**Acceptance Scenarios**:

1. **Given** 用户在设置页面查看已选中的中配或高配目标模型信息，**When** 该档位涉及投机解码相关配置，**Then** 用户能够看到与草稿模型相关的说明性信息，包括推荐候选规格（Qwen2.5-0.5B-Instruct / Qwen2.5-1.5B-Instruct）、"下载其一即可自动搭配当前目标模型使用、无需手动指定"的说明，以及未配置时的提示文案（2026-10-20 澄清，见 FR-004/FR-006/FR-007）。

---

### User Story 3 - 用户未配置草稿模型时系统行为可预期 (Priority: P2)

用户切换到中配或高配档位，但尚未下载/配置本特性要求的草稿模型文件。用户期望在此情况下应用仍然可以正常完成翻译任务，不会因为缺少一个可选的加速组件而导致功能不可用或报错。

**Why this priority**：这是保障功能可用性下限的兜底场景，优先级与 User Story 2 相当，均服务于 User Story 1 的可落地性，故列为次优先级。

**Independent Test**：在未放置任何草稿模型文件的环境下，切换为中配或高配目标模型并触发一次慢流生成，验证生成成功完成并产出正确内容，且设置页面展示明确提示告知用户当前未启用投机解码加速及原因（FR-006，2026-10-20 澄清）。

**Acceptance Scenarios**:

1. **Given** 用户已切换为中配或高配目标模型，但未配置本特性要求的草稿模型，**When** 用户输入一段草稿文本触发慢流生成，**Then** 系统仍能成功完成生成并产出与既有单模型生成路径一致的翻译结果，不因缺少草稿模型而导致生成失败或应用崩溃；**And** 设置页面给出明确提示，告知用户当前未启用投机解码加速及原因（FR-006，2026-10-20 澄清）。

### Edge Cases

- 用户此前已按本特性要求配置了草稿模型，之后又在设置页面将目标模型切换为另一档位（如从中配切至高配）：由于草稿模型与目标模型的搭配关系由应用自动固定（FR-007，2026-10-20 澄清），切换目标模型档位后，应用 MUST 自动重新匹配该新档位对应的默认草稿模型；若用户尚未下载新档位对应的候选草稿模型规格，则按 FR-006 既定行为静默降级并在设置页面给出提示，具体匹配与检测时机留待 `/speckit.plan` 阶段具体设计。
- 草稿模型文件存在但已损坏或格式不兼容（无法被 llama.cpp 加载）：系统行为 MUST 与 User Story 3（未配置草稿模型）的既定兜底行为一致，退化为既有单模型生成路径，不得因草稿模型加载失败而导致目标模型本身也无法完成生成。
- 用户在生成过程中（投机解码已开始执行）切换模型档位或关闭浮窗：该场景延续 001/002/003 已确立的既有会话中断/取消处理逻辑，本特性不改变该既有行为，新增的草稿模型实例生命周期管理须遵循相同的清理时机。
- 低配默认档位（Qwen2.5-3B-Instruct）本身延迟已满足 001 SC-003 阈值，MUST NOT 为其叠加投机解码（FR-005，2026-10-20 澄清：仅中配、高配两档启用），该档位既有生成路径保持 003 交付时的状态不变。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在中配或高配目标模型档位下，支持引入一个独立的、参数规模更小的"草稿模型"，在目标模型生成过程中由草稿模型快速产出候选 token 序列，再由目标模型一次性批量验证，验证通过的 token 直接采纳，免去目标模型对该部分 token 的逐一自回归前向计算，从而降低整句生成延迟；最终生成结果的采纳逻辑 MUST 确保与目标模型独立逐 token 生成时在语义上等价，不因引入草稿模型而降低翻译质量。
- **FR-002**: 投机解码能力 MUST 仅作为 `LlmEngine` 内部推理实现细节的扩展引入，MUST NOT 改变 `LlmEngine::generate()` 的对外签名（输入输出均为 `QString`），MUST NOT 改变 001/002/003 已确立的 QML↔C++ 会话契约（`contracts/qml-cpp-session-interface.md`）。
- **FR-003**: 投机解码能力 MUST NOT 改变或移除 003 已引入的 GBNF 语法约束采样（003 FR-005～FR-009）；草稿模型产出的候选 token 序列在被目标模型批量验证时，MUST 同样遵循既有语法约束规则，不得使约束失效或被绕过。
- **FR-004**: 系统 MUST 在设置页面提供多个候选草稿模型规格（如 Qwen2.5-0.5B-Instruct / Qwen2.5-1.5B-Instruct 两档）作为推荐下载项，供用户按自身设备性能情况自行选择下载其中之一；该推荐下载项 MUST 沿用 002/003 已确立的三档主模型"推荐但需用户手动下载/放置"既有模式，MUST NOT 新增任何模型文件的网络自动下载能力（2026-10-20 澄清，见 Clarifications）。
- **FR-005**: 投机解码能力 MUST 仅对中配、高配两档目标模型启用；低配默认档位（Qwen2.5-3B-Instruct）MUST NOT 启用投机解码——该档位既有延迟已满足 001 SC-003 阈值，叠加投机解码需额外承担草稿模型带来的内存/显存占用但收益有限（2026-10-20 澄清，见 Clarifications）。
- **FR-006**: 当用户已选定需要投机解码的目标模型档位，但未下载/未配置对应草稿模型时，系统 MUST 静默降级为不启用投机解码的既有单模型生成路径（生成过程本身不中断、不报错），同时 MUST 在设置页面给出明确的提示信息，告知用户当前未启用投机解码加速及原因（如"未检测到草稿模型，投机解码未启用"）；系统 MUST NOT 因草稿模型缺失而导致生成失败或应用不可用（2026-10-20 澄清，见 Clarifications）。
- **FR-007**: 草稿模型与目标模型之间的搭配关系 MUST 由应用根据当前选定的目标模型档位（中配/高配）自动固定搭配一个默认草稿模型，用户 MUST NOT 需要在设置页面手动选择/指定该搭配关系；用户仅需在 FR-004 已确定的候选规格（Qwen2.5-0.5B-Instruct / Qwen2.5-1.5B-Instruct）中下载其中之一，应用据此自动识别并将其用于当前目标模型档位的投机解码搭配（2026-10-20 澄清，见 Clarifications）。
- **FR-008**: 系统 MUST NOT 改变 001 SC-003 既有延迟阈值定义的文字本身（"首批内容延迟 < 300 毫秒、整句生成延迟 < 800 毫秒"，仅对低配默认模型强制适用，002/003 已对其适用范围做过修订），本特性对中/高配档位延迟的改善 MUST 以"相较不启用投机解码时的自身延迟有可测量的降低"衡量，MUST NOT 要求中/高配档位达到该阈值本身。
- **FR-009**: 本特性 MUST NOT 改变 001 已确立的低配默认档位延迟表现与既有交互行为；低配默认档位（Qwen2.5-3B-Instruct）的既有生成路径 MUST 保持 003 交付时的状态不变，不启用投机解码、不加载草稿模型（FR-005，2026-10-20 澄清）。

### Key Entities *(include if feature involves data)*

- **草稿模型（Draft Model）**：投机解码中负责快速猜测候选 token 序列的辅助模型，参数规模显著小于目标模型；推荐型号为 Qwen2.5-0.5B-Instruct / Qwen2.5-1.5B-Instruct 两档候选规格（FR-004，2026-10-20 澄清），获取方式沿用"推荐但需用户手动下载/放置"既有模式；与目标模型的搭配关系由应用根据目标模型档位自动固定（FR-007，2026-10-20 澄清），用户无需手动指定搭配。
- **投机解码配置（Speculative Decoding Profile）**：描述"目标模型档位 → 是否启用投机解码 → 对应草稿模型"的映射关系；启用范围（FR-005，2026-10-20 澄清：仅中配、高配启用，低配不启用）、未配置时的行为（FR-006，2026-10-20 澄清：静默降级+设置页面明确提示）均已确定，具体字段结构留待 `/speckit.plan` 阶段确定。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：在已正确配置草稿模型的前提下，用户切换为中配目标模型后执行一次整句生成，其生成延迟相较同一测试样例在不启用投机解码时的既有延迟有可测量的降低。
- **SC-002**：在已正确配置草稿模型的前提下，用户切换为高配目标模型后执行一次整句生成，其生成延迟相较同一测试样例在不启用投机解码时的既有延迟有可测量的降低。
- **SC-003**：在覆盖多种输入场景的测试语料集合上，比较"启用投机解码"与"不启用投机解码"两种路径对同一输入产出的最终标准中文文本，二者在语义正确性上保持一致，不出现因引入投机解码而导致的翻译质量下降，该结论对测试语料集合的验证通过率达到 100%。
- **SC-004**：用户未配置草稿模型时，切换为中配或高配目标模型并执行生成任务，生成功能本身的成功率与既有（003 交付时）单模型生成路径保持一致，不因草稿模型缺失而出现生成失败或应用崩溃。
- **SC-005**：低配默认档位用户（FR-005，2026-10-20 澄清：低配默认档位不启用投机解码）的既有延迟体验（001 SC-003 阈值）与既有交互行为在本特性交付后保持与 003 交付时一致，不受本特性影响。

## Assumptions

- 本特性以 `specs/001-floating-ime-converter`、`specs/002-lattice-dict-model-switch`、`specs/003-model-tier-perf-tuning` 三项已交付特性为既有基线；除本 spec 背景章节明确声明取代/新增的条款外，001/002/003 既有 Functional Requirements、Success Criteria、Edge Cases 原样继续有效。
- 投机解码在"验证阶段确保与目标模型独立解码结果等价"这一前提下是无损加速技术——草稿模型的猜测仅用于加速目标模型的验证过程，不改变目标模型最终采纳的 token 序列本身，这是 003 spec 背景中已记录、llama.cpp 官方文档描述的该技术本身的数学性质，而非本特性的产品决策，故 FR-001/SC-003 据此撰写验收标准，不作为待澄清事项。
- llama.cpp 作为本仓库既有慢流推理底层依赖（001/002/003 已确立）原生支持投机解码机制，具体接入方式（API 调用形式、草稿-验证调度的具体实现）留待 `/speckit.plan` 设计阶段的 research 环节确定，不改变本 spec 已声明的"不改变 `LlmEngine::generate()` 对外签名"这一约束。
- 本特性引入草稿模型后会同时加载草稿模型与目标模型两个独立的推理实例，相应增加内存/显存占用；具体占用数值与是否因此需要对低配设备额外设置准入门槛，留待 research/实现阶段以实测数据记录，本 spec 不对具体占用数值做强约束性断言。

## Out of Scope

- **动态自动调整投机解码窗口大小等自适应优化**：本特性不实现"根据运行时验证通过率动态调整每轮草稿 token 数量"一类更高级的自适应调度机制；除非 `/speckit.plan` 阶段的 research 环节发现固定窗口大小在技术上不可行、必须引入某种基础的自适应机制才能完成本特性已声明的 FR-001，否则该类优化留待后续专项评估。
- **修改 001 SC-003 延迟阈值定义文字本身**：001 SC-003 的"首批内容延迟 < 300 毫秒、整句生成延迟 < 800 毫秒"阈值定义及其"仅对低配默认模型强制适用"的适用范围（002/003 已修订）不在本特性变更范围内；本特性仅尝试通过投机解码让中/高配档位更快地改善延迟表现，不改变该条款的文字本身。
- **投机解码加速倍数的具体数值承诺**：本 spec 不在规格阶段断言具体加速倍数（如"1.5~3 倍"等 003 背景中引用的公开资料数据仅为背景参考），实际加速效果留待实现完成后以实测数据记录于 research/plan 产出中。
- **草稿模型的自动下载机制**：延续 002/003 已确立的"推荐但需用户手动下载/放置模型文件"既有模式，草稿模型的两档候选推荐规格（Qwen2.5-0.5B-Instruct / Qwen2.5-1.5B-Instruct，FR-004，2026-10-20 澄清）同样适用该模式，本特性不新增任何模型文件的网络自动下载能力。
