# Feature Specification: 学习提示气泡内容生成

**Feature Branch**: `005-learning-tip-generation`

**Created**: 2026-10-20

**Status**: Draft

**Input**: User description: "这是对已交付的 001-floating-ime-converter 中一直留空的'学习提示气泡'功能的内容生成实现。001 的 spec.md 定义了学习提示（可选）：围绕本次输入/输出生成的简短英文表达建议文本，MVP 内仅作纯文本展示；FR-002 要求浮窗三段式布局中包含该区域。docs/IME.md §2.2'动态自愈界面'对此有更具体描述：学习气泡展示'用户应该如何用地道英文表达同样意思'的建议，呼应产品'逆向输出范式：输入英/混杂文本，输出标准中文；但同时展示如果用纯正英文该怎么说，帮助用户学习地道英文表达'的核心理念（docs/IME.md §1.2）。当前代码现状：SessionController 已声明 learningTipText/learningTipVisible 只读属性，FloatingWindow.qml 已有对应展示区域，但这两个属性从未被赋予有意义的内容——learningTipText 始终为空字符串、learningTipVisible 始终为 false，该区域在当前版本中实际上从未真正展示过任何内容；LlmEngine::generate() 的系统提示词仅要求模型输出标准中文译写结果，完全没有涉及同时生成英文表达建议这个任务。本特性需要补齐这部分内容生成能力，使学习提示气泡真正展示与本次输入/输出相关的地道英文表达建议。"

**语言（宪章《语言与文档规范》）**：用户故事、验收场景、功能需求、成功标准等说明性文字 MUST 使用简体中文；类名、路径、协议等技术标识可保留英文。

## Clarifications

### Session 2026-10-21

- Q: 英文表达建议应如何生成？ → A: 方案一——复用同一次慢流模型调用，使其在生成"标准中文译写结果"的同时一并生成"对应的英文表达建议"（调整 prompt/输出格式，一次调用产出两部分内容），不触发第二次独立的模型调用。
- Q: 学习提示内容应展示到什么详尽程度？ → A: 仅展示"地道英文表达本身"（如 "I'm not that hungry today..."），不额外展示关键语法点提示。
- Q: 该功能是否应允许用户在设置页面关闭/开启？ → A: 需要，在设置页面提供开关，默认开启；用户可随时主动关闭该功能。
- Q: 低配/中配/高配不同档位模型是否都需要生成学习提示内容？ → A: 仅中配、高配两档目标模型启用学习提示生成；低配默认档位（Qwen2.5-3B-Instruct）不生成学习提示内容，保持其现有延迟预算不变（与 004-speculative-decoding 对投机解码启用范围的既有处理方式一致）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 译写同时看到地道英文表达建议 (Priority: P1)

用户像使用 001 已交付的浮窗转换器一样，输入中英拼音混杂的草稿文本并等待标准中文输出预览生成完毕。与 001 当前实际表现不同的是，用户这次在浮窗第三区域（学习提示气泡）中看到一条与本次输入/输出语义相关的英文表达建议文本——提示"如果用更地道的英文，这句话可以怎么说"。用户在不打断原有确认流程（仍可直接按回车上屏标准中文结果）的前提下，顺带读到这条建议，从而潜移默化地积累"想表达的意思 → 地道英文说法"的对应关系，呼应 docs/IME.md 的产品初衷。

**Why this priority**：这是本特性唯一的核心交付目标——让 001 中一直留空、从未真正展示过内容的学习提示区域首次产生有意义的内容。没有这条路径，该区域将继续保持空白，特性本身没有兑现任何价值。

**Independent Test**：在浮窗转换器中输入一段典型的中英拼音混杂草稿（如"wo today bushi very e"），等待标准中文输出预览生成完毕后，验证学习提示气泡区域是否同时展示出非空的英文表达建议文本，且该文本在语义上能让用户辨认出与本次输入/输出的对应关系。

**Acceptance Scenarios**:

1. **Given** 用户已输入完一句中英拼音混杂草稿，**When** 慢流处理生成标准中文输出预览完成，**Then** 浮窗学习提示气泡区域 MUST 同步展示一条非空的英文表达建议文本，且该区域从不可见状态变为可见状态。
2. **Given** 学习提示气泡已展示建议文本，**When** 用户阅读该文本，**Then** 用户能够识别出该英文表达与本次输入/输出表达的是同一个意思（而非与当前会话无关的通用文本或占位内容）。
3. **Given** 学习提示气泡已展示内容，**When** 用户按下确认键（回车）将标准中文结果上屏，**Then** 学习提示内容的展示与消失 MUST 与 001 已定义的"轻量退出、不阻碍日常交流节奏"的既有气泡生命周期保持一致，不得阻塞或延迟原有的确认与上屏流程。
4. **Given** 用户持续修改原始输入导致标准中文输出预览重新生成（见 001 FR-005），**When** 新一轮生成完成，**Then** 学习提示气泡内容 MUST 同步更新为与最新一轮输入/输出相关的建议，不得停留在已过时的上一轮内容。

---

### User Story 2 - 生成失败或不可用时气泡保持沉默而非展示错误/陈旧内容 (Priority: P2)

用户在本地模型缺失、推理异常，或本轮输入过于简短/无法形成有意义建议等场景下使用该功能。此时学习提示气泡不会展示报错信息、乱码、占位符或者上一轮残留的陈旧建议，而是与 001 已定义的"学习提示气泡可选、低优先级"语义保持一致，直接保持不可见，不干扰用户对标准中文译写结果这一核心功能的正常使用。

**Why this priority**：这是避免本特性引入新的"半成功/半失败"不一致状态、保证不回退 001 已确立的"浮窗保持可操作、不崩溃、不展示令人困惑信息"基线（001 FR-011/SC-006）的必要兜底路径，但不影响 User Story 1 已验证的核心价值，因此排在 P2。

**Independent Test**：在本地模型缺失或推理异常的环境下唤起浮窗并尝试输入，验证学习提示气泡区域是否保持不可见、不展示任何报错或残留内容，且不影响浮窗其余区域（原始输入槽、中文输出预览）已有的异常提示行为。

**Acceptance Scenarios**:

1. **Given** 本地大语言模型文件缺失、损坏或推理异常（见 001 FR-011），**When** 用户尝试输入并触发慢流处理，**Then** 学习提示气泡 MUST 保持不可见状态，不得展示任何报错文案、乱码或占位符。
2. **Given** 标准中文输出预览本轮未能成功生成，**When** 系统判定本轮慢流处理失败，**Then** 学习提示气泡 MUST NOT 单独展示"部分成功"的英文建议内容（即不得出现标准中文译写失败、但学习提示仍展示上一轮或无关内容的不一致状态）。

---

### Edge Cases

- 当本轮输入内容过短或过于简单（如仅一个词、无完整语义）时，是否仍需生成学习提示内容，还是直接判定为"无需提示"并保持气泡不可见？
- 当用户连续快速修改输入、多轮慢流处理相继触发时，学习提示内容如何与最新一次标准中文输出预览保持同步，避免用户看到的英文建议与当前中文预览内容不对应？
- 当标准中文输出预览因用户继续编辑而发生较大幅度修正（自愈）时，学习提示内容是否必须等待新一轮生成完全结束才更新，还是允许短暂展示与新预览不完全对应的旧内容？
- 当本轮输入内容本身已经是相当地道的英文表达（纠偏空间很小）时，学习提示展示什么内容（例如是否允许与当前输出相似甚至重复）？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在慢流处理为本轮输入生成标准中文译写结果的同一次模型调用中，一并产出与本次输入/输出语义相关的英文表达建议文本（即调整现有 prompt/输出格式，使模型单次调用同时输出"标准中文译写结果"与"英文表达建议"两部分内容），用于填充 001 已声明的 `learningTipText` 属性；MUST NOT 为生成该建议文本而触发第二次独立的模型调用。
- **FR-002**: 当本轮英文表达建议内容成功产出且判定为有效（非空、与本轮输入/输出相关）时，系统 MUST 将 `learningTipVisible` 置为可见，使浮窗第三区域（学习提示气泡）按 001 FR-002 已定义的纯文本静态展示方式呈现该内容。
- **FR-003**: 学习提示内容 MUST 仅展示"地道英文表达本身"（如 "I'm not that hungry today..." 一类完整句子），MUST NOT 额外附加关键语法点提示文字或其他讲解性内容。
- **FR-004**: 当本轮慢流处理失败（如 001 FR-011 所述模型缺失/损坏/推理异常场景）、或判定本轮无法产出有意义的英文表达建议时，系统 MUST 将 `learningTipVisible` 保持或恢复为不可见，MUST NOT 展示报错文案、乱码、占位符，或残留上一轮已过时的建议内容。
- **FR-005**: 当标准中文输出预览因用户持续编辑原始输入而重新触发生成（见 001 FR-005）时，学习提示内容 MUST 随之重新生成并更新展示，与最新一轮的输入/输出保持对应。
- **FR-006**: 学习提示内容的展示与隐藏节奏 MUST 沿用 001 FR-002/Out of Scope 已确立的"仅做纯文本静态展示，不要求动画或打字机式自愈效果"的边界，本特性 MUST NOT 新增该区域的动画或渐进呈现效果。
- **FR-007**: 本特性 MUST NOT 引入对学习提示内容、用户学习历史或学习进度的任何持久化存储、生词本或个性化学习记忆能力，沿用 001/002/003 已确立的边界。
- **FR-008**: 系统 MUST 在设置页面提供一个开关，允许用户开启或关闭学习提示气泡展示功能；该开关 MUST 默认处于开启状态。用户关闭该开关后，系统 MUST 保持 `learningTipVisible` 为不可见，不再生成或展示学习提示内容，且该设置变更 MUST NOT 影响浮窗其余区域（原始输入槽、中文输出预览）的既有行为。
- **FR-009**: 学习提示内容生成能力 MUST 仅在中配、高配两档目标模型（见 003-model-tier-perf-tuning 已确立的三档结构）下启用；低配默认档位（Qwen2.5-3B-Instruct）MUST NOT 生成或展示学习提示内容，以保持该档位现有的延迟预算不变（与 001 Clarifications 中"SC-003 延迟阈值仅对低配默认模型强制适用"及 004-speculative-decoding 对投机解码启用范围的既有处理方式保持一致）。

### Key Entities *(include if feature involves data)*

- **学习提示建议（Learning Tip Suggestion）**：围绕本轮输入/输出生成的英文表达建议文本，是 001 已声明的 `learningTipText` 属性在本特性中首次被赋予的实际内容来源；不引入独立的持久化数据模型，生命周期与本轮会话的标准中文输出预览保持一致（随输入变化而重新生成，不跨会话保留）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：在典型使用场景下（用户使用中配或高配档位模型，完成一次完整的中英拼音混杂草稿到标准中文输出预览的生成流程，且学习提示开关处于默认开启状态），用户能够看到与本次输入/输出语义相关的非空英文表达建议内容，而不再是 001 当前实际表现中始终空白的学习提示区域。低配默认档位按 FR-009 不生成学习提示内容，不适用本条标准。
- **SC-002**：用户无需任何额外操作（如点击展开、二次确认）即可在学习提示气泡中读到完整的建议语句。
- **SC-003**：在抽样的真实中英混杂草稿输入场景下，用户能够从学习提示内容中辨认出其与当前输入/输出表达的是同一个意思，而非感觉与本轮会话无关的通用文本。
- **SC-004**：在本地模型缺失、推理异常，或本轮判定无法产出有效建议的场景下，学习提示区域始终保持不可见、不展示报错或令人困惑的内容，用户对浮窗核心功能（标准中文译写）的使用不受影响。
- **SC-005**：用户持续编辑原始输入触发多轮重新生成时，学习提示内容与最新一轮的标准中文输出预览保持对应，不出现用户可感知的"建议与当前预览内容不符"的情况。

## Assumptions

- 本特性复用 001 已声明但从未被赋值的 `learningTipText`/`learningTipVisible` 只读属性与 `FloatingWindow.qml` 中已存在的纯文本展示区域作为呈现载体，不改变该区域已确立的"纯文本、无动画"展示方式（见 001 FR-002、Out of Scope）；本特性仅补齐这两个属性的内容生成逻辑。
- 本特性不改变 001 已确立的核心确认/上屏流程（回车确认标准中文结果并触发剪贴板写入与粘贴尝试），学习提示内容的生成与展示 MUST 是该流程之外的附加信息，不得阻塞或改变标准中文结果的生成与上屏时序。
- 001 Assumptions 中原有的"学习提示气泡在 MVP 阶段的内容来源可直接复用本次慢流生成过程中产生的辅助信息（如有），不要求额外的独立生成流程"这一假设，在实际实现中并未被满足（当前代码从未生成任何此类内容）；本特性即是对这一遗留缺口的正式补齐。经 Clarifications（2026-10-21）确认，该生成流程仍归属于"同一次慢流生成过程中产生"（FR-001 的方案一），上述 001 原有假设在本特性中得到延续并正式落地。

## Out of Scope

- 学习提示气泡的精细动画效果与"打字机式"自愈呈现；沿用 001 已明确排除的边界，本特性仅做纯文本静态展示，不新增任何动画或渐进呈现效果。
- 用户个人生词本、个性化学习记忆、学习进度统计等任何形式的个性化学习数据能力；沿用 001/002/003 已明确排除的边界，本特性不涉及学习提示内容的持久化存储或跨会话记忆。
- 系统级输入法框架接入、LoRA 模型微调/训练管道等 001 已排除的事项；本特性不重新讨论这些边界。
- 学习提示内容的多语言呈现（如非英文学习者场景）；本特性延续 docs/IME.md 的产品定位，仅针对"英文表达建议"这一既定场景。
