# Feature Specification: AI 辅助双语浮窗转换器（MVP）

**Feature Branch**: `001-floating-ime-converter`

**Created**: 2026-10-16

**Status**: Draft

**Input**: User description: "基于 docs/IME.md《AI 辅助英语输出输入法》产品愿景裁剪出的 MVP 范围：不做系统级输入法框架接入，而是做一个跨平台（Windows/macOS/Linux）'浮窗转换器'——全局热键唤起 Qt/QML 无边框浮窗，用户输入中英拼音混杂草稿文本，本地双流管道（快流本地词典纠错 + 慢流本地 LLM 生成标准中文）处理后，用户确认（回车）即把结果写入系统剪贴板并尝试模拟 Cmd/Ctrl+V 自动粘贴到此前获得焦点的目标应用；平台/合成器不支持自动注入时（典型 Linux Wayland）降级为'已复制到剪贴板，请手动粘贴'提示。明确排除：真系统级输入法框架接入、LoRA/模型微调、个性化学习记忆、精细动画自愈效果、Wayland 无感注入。"

**语言（宪章《语言与文档规范》）**：用户故事、验收场景、功能需求、成功标准等说明性文字 MUST 使用简体中文；类名、路径、协议等技术标识可保留英文。

## Clarifications

- Q: "可直接使用或仅需极少修改"的比例应达到多少才算验收通过？ → A: 60%。

### Session 2026-10-19（002-lattice-dict-model-switch 实施阶段触发的交叉修订）

- Q: 002 特性引入"模型可切换"后，用户可选用参数规模更大的中/高配模型（Qwen2.5-14B/32B-Instruct）；本机真实实测显示中配 Qwen2.5-14B 整句生成耗时约 2.6 秒，超出本条款原定 800 毫秒阈值约 3.2 倍（但翻译语义质量更好，纠正了低配 3B 模型同场景下的误译）。SC-003 的延迟阈值是否仍对所有可选模型统一适用？ → A: 不再统一适用。SC-003 的 300ms/800ms 阈值 **仅对低配默认模型（Qwen2.5-3B-Instruct）强制适用**；用户主动在设置页面切换为中配/高配模型时，视为用户已知情地以更长延迟换取更高翻译质量，MUST NOT 要求中/高配模型满足本条款的延迟阈值。具体中/高配模型的延迟预期由 002 特性的 research.md/tasks.md 实测记录承载，不在本条款内重复定义数值。


## User Scenarios & Testing *(mandatory)*

### User Story 1 - 混杂草稿一键转换为标准中文并自动上屏 (Priority: P1)

用户正在使用电脑上的任意应用（如聊天工具、文档编辑器、邮件客户端）撰写中文内容，但习惯用英语组织思路、夹杂少量中文拼音或简拼草稿。用户按下全局热键唤起一个无边框浮窗，在浮窗中输入中英拼音混杂的草稿文本；浮窗一边实时展示快流纠错后的规整化原始输入，一边在后台异步生成标准中文的"输出预览"。用户看到预览结果满意后按下回车确认，浮窗消失，标准中文文本被写入系统剪贴板，并自动模拟粘贴操作，出现在用户此前正在编辑的目标应用输入框内，用户可以继续原地编辑或发送，无需手动切换窗口或手动粘贴。

**Why this priority**：这是产品的核心价值闭环——"输入英中混杂草稿，输出地道标准中文并直接可用"。没有这条路径，其余一切功能都没有意义；这也是验证双流管道端到端延迟与可用性的首个完整可演示场景。

**Independent Test**：在 macOS 或 Linux X11 环境下，准备一个已聚焦的文本输入框（如备忘录或文本编辑器），按热键唤起浮窗，输入一段中英拼音混杂文本，等待输出预览就绪后按回车，验证标准中文文本是否无需额外手动操作即出现在原输入框中。

**Acceptance Scenarios**:

1. **Given** 用户已将光标聚焦在某应用的文本输入框中，**When** 用户按下全局热键，**Then** 浮窗在该应用前景弹出且处于可输入状态，原目标应用的焦点信息被记录以供后续粘贴使用。
2. **Given** 浮窗已唤起，**When** 用户逐字输入中英拼音混杂文本，**Then** 浮窗的"原始输入槽"区域实时展示经快流本地词典/拼音纠错后的规整化文本，用户主观感受不到输入卡顿。
3. **Given** 用户已输入完一句或一段草稿，**When** 慢流本地模型处理完成，**Then** 浮窗的"中文输出预览"区域展示对应的标准中文译写结果，且在用户按下回车前该结果已基本就绪可供阅读确认。
4. **Given** 浮窗展示了中文输出预览，**When** 用户按下回车确认，**Then** 浮窗关闭，预览内容被写入系统剪贴板，系统尝试模拟粘贴操作，使该内容出现在此前记录的目标应用输入框内。
5. **Given** 用户对当前输出预览不满意，**When** 用户继续编辑原始输入文本，**Then** 系统重新触发慢流生成，输出预览随之更新，直到用户确认或取消。
6. **Given** 浮窗已唤起但用户改变主意，**When** 用户按下取消键（如 Esc）或再次按下热键，**Then** 浮窗隐藏，不产生任何剪贴板写入或粘贴动作，目标应用内容不受影响。

### User Story 2 - 不支持自动粘贴注入环境下的手动粘贴降级 (Priority: P2)

用户在某些平台或窗口合成环境下（典型为 Linux Wayland 桌面）使用本功能。由于系统安全模型限制，应用无法模拟按键将文本自动注入到其他应用窗口。此时用户完成浮窗内的转换确认后，系统不会尝试静默失败或报错崩溃，而是明确告知"已复制到剪贴板，请手动粘贴"，用户可自行切换到目标应用并手动执行粘贴，仍然获得标准中文转换结果。

**Why this priority**：这是保证功能在生态受限平台上依然"可用而不是不可用"的关键兜底路径，紧随核心闭环之后交付，确保 Linux Wayland 用户不会遇到无提示的静默失败。

**Independent Test**：在已知不支持自动粘贴注入的合成器环境下运行浮窗，完成一次输入确认，验证剪贴板中已包含正确的标准中文内容，且浮窗/系统给出清晰的"请手动粘贴"提示而非报错或无反应。

**Acceptance Scenarios**:

1. **Given** 当前运行环境的平台/窗口合成器不支持模拟粘贴注入，**When** 用户按下回车确认输出预览，**Then** 标准中文结果被写入系统剪贴板，同时界面明确提示"已复制到剪贴板，请手动粘贴"。
2. **Given** 用户看到了手动粘贴提示，**When** 用户切换到目标应用并执行粘贴（如 Ctrl+V），**Then** 剪贴板中的标准中文内容被正确粘贴到目标输入框，内容与浮窗确认前展示的输出预览一致。

---

### User Story 3 - 管道/注入异常时的友好提示而非崩溃 (Priority: P3)

用户在使用过程中遇到环境异常，例如本地 AI 模型文件缺失或损坏、慢流推理耗时异常、或自动粘贴注入尝试失败（即便平台理论上支持）。此时浮窗不会无响应或崩溃，而是给出用户能理解的提示信息，告知发生了什么以及用户可以如何处理（例如重试、检查模型文件、手动粘贴），保证功能在异常路径下依然处于可控、可解释状态。

**Why this priority**：这是补齐跨平台落地前最后一块"可用性边界"，保证 MVP 不会因为环境差异（尤其是首次安装、模型未就绪、权限未授予等常见情况）给用户造成困惑或信任流失，但不影响核心闭环已验证的价值，因此排在 P3。

**Independent Test**：分别在"本地模型文件被移除"和"人为制造注入失败（如撤销系统权限）"两种条件下运行浮窗并走完一次确认流程，验证系统均给出可理解的提示文案而不是无提示失败、报错堆栈或程序崩溃。

**Acceptance Scenarios**:

1. **Given** 本地 LLM 模型文件缺失或无法加载，**When** 用户唤起浮窗并尝试输入，**Then** 系统提示用户当前标准中文生成功能不可用及可能原因，且浮窗不崩溃、不无响应。
2. **Given** 慢流推理耗时显著超出预期，**When** 用户已等待但输出预览长时间未就绪，**Then** 系统给予用户可感知的等待状态提示，而不是让界面看起来冻结或无反馈。
3. **Given** 模拟粘贴注入在本应支持的平台上执行失败（如目标权限未授予），**When** 用户确认输出预览，**Then** 系统至少保证标准中文内容已写入剪贴板，并提示用户注入未成功、可手动粘贴。

---

### Edge Cases

- 用户按下全局热键时，桌面上当前没有任何已聚焦的应用窗口（例如聚焦在桌面空白处），此时确认后应将内容粘贴到何处？
- 慢流尚未生成完成输出预览时，用户提前按下确认键（回车），系统应如何处理（等待、使用尚不完整的结果、还是提示用户稍候）？
- 目标应用窗口在浮窗唤起期间被用户手动切换、最小化或关闭，确认时原目标应用已不可用，粘贴动作应如何表现？
- 用户在浮窗中未输入任何内容即按下确认键，是否应产生任何剪贴板写入或粘贴动作？
- 全局热键与用户系统上已有的其他快捷键发生冲突，用户如何察觉并处理？
- macOS 上用户尚未授予辅助功能（Accessibility）权限，模拟粘贴注入无法执行时，与 Wayland 不支持注入的降级路径呈现相同的统一提示文案"已复制到剪贴板，请手动粘贴"（见 FR-012）。
- 剪贴板内容在系统自动粘贴动作执行前被其他程序意外覆盖。
- 用户输入的草稿文本过长（远超一般聊天场景句子长度）时，浮窗三段式布局的展示与慢流处理时间如何保持可用体验。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供一个跨平台（Windows/macOS/Linux）的全局热键，用于唤起与隐藏浮窗，唤起时浮窗 MUST 记录当前已获得系统焦点的目标应用窗口信息，供后续粘贴使用。默认热键组合为 Ctrl+Alt+Space（macOS 对应 Control+Option+Space）。
- **FR-002**: 浮窗 MUST 以无边框窗口形式呈现，并包含三个区域：原始输入槽（展示用户实时击键后的规整化文本）、中文输出预览（展示标准中文结果，确认后即为上屏内容）、学习提示气泡（可选、低优先级，MVP 内仅做纯文本展示，不要求动画效果）。
- **FR-003**: 系统 MUST 对用户在原始输入槽中的击键内容进行同步、即时的本地纠错与规整化（基于本地词典/拼音简拼匹配与物理键位邻近度的编辑距离加权），全过程不依赖网络连接或本地大模型推理，目标端到端延迟低于 15 毫秒，使用户在视觉上不察觉卡顿。
- **FR-004**: 系统 MUST 在原始输入发生变化后，以防抖（即不对每次击键都触发，而是在输入趋于稳定后触发）方式异步调用本地大语言模型推理，生成对应的标准中文译写结果，并将结果展示在中文输出预览区域；该结果 MUST 在用户按下确认键之前基本就绪（即通常情况下用户确认时已有预览可看）。
- **FR-005**: 用户 MUST 能够在浮窗保持打开期间持续修改原始输入文本，每次修改 MUST 促使中文输出预览基于最新原始输入重新生成并更新展示。
- **FR-006**: 用户 MUST 能够通过一个确认键（回车）将当前中文输出预览结果标记为最终上屏内容，并触发后续的剪贴板写入与粘贴尝试；用户 MUST 能够通过一个取消操作（如 Esc 或再次触发热键）关闭浮窗且不产生任何剪贴板写入或粘贴动作。
- **FR-007**: 用户确认后，系统 MUST 将最终中文文本写入系统剪贴板。
- **FR-008**: 完成剪贴板写入后，系统 MUST 尝试模拟标准粘贴操作（Windows/Linux 为 Ctrl+V，macOS 为 Cmd+V），将剪贴板内容注入此前记录的目标应用输入框，使用户无需手动切换窗口或手动执行粘贴。
- **FR-009**: 当系统检测到当前平台或窗口合成环境不支持模拟粘贴注入（典型为 Linux Wayland 桌面环境）时，系统 MUST 在完成剪贴板写入后明确提示用户"已复制到剪贴板，请手动粘贴"，且 MUST NOT 将此情况当作错误或异常中断处理。
- **FR-010**: 系统 MUST 在 Windows、macOS、Linux 三个桌面平台上均可运行浮窗转换器的核心交互流程（热键唤起、输入、双流处理、确认）；自动粘贴注入能力 MUST 至少在 macOS 与 Linux X11 环境下可用，Windows 与其余 Linux 合成环境下的注入支持程度以平台能力为准。
- **FR-011**: 当本地大语言模型文件缺失、损坏或无法加载时，系统 MUST 以用户可理解的方式提示该情况，且 MUST NOT 导致浮窗无响应或程序崩溃。
- **FR-012**: 当模拟粘贴注入尝试失败时（无论原因为平台/合成器不支持，还是权限未授予等其他情况），系统 MUST 保证标准中文文本已成功写入剪贴板，并 MUST 统一提示用户"已复制到剪贴板，请手动粘贴"，不区分具体失败原因、不展示差异化文案。
- **FR-013**: 系统所依赖的本地大语言模型 MUST 为开源、可本地离线运行的量化模型，具体采用 Qwen2.5-3B-Instruct，使用 GGUF Q4_K_M 量化精度。

### Key Entities *(include if feature involves data)*

- **原始输入草稿**：用户在浮窗中实时击键产生的中英拼音混杂文本，是快流处理的输入来源。
- **规整化候选文本**：原始输入草稿经快流本地词典/拼音纠错后的展示结果，呈现在"原始输入槽"区域，不构成最终上屏内容。
- **标准中文输出预览**：慢流本地大语言模型基于规整化候选文本生成的标准中文译写结果，是用户确认后成为最终上屏内容的来源。
- **目标应用焦点上下文**：浮窗被唤起瞬间记录的、此前获得系统焦点的应用窗口信息，用于确认后定位自动粘贴的目标位置。
- **学习提示（可选）**：围绕本次输入/输出生成的简短英文表达建议文本，MVP 内仅作纯文本展示，不涉及持久化或个性化记忆。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：用户从按下全局热键到浮窗出现并可接受输入之间的等待，在用户主观体验上是即时的，不构成可感知的卡顿。
- **SC-002**：用户在浮窗中击键后，原始输入槽内的规整化纠错展示更新延迟低于 15 毫秒，用户持续输入时感受不到输入滞后。
- **SC-003**：在普通消费级 CPU 环境下，**使用低配默认模型（Qwen2.5-3B-Instruct）时**，用户输入稳定后至中文输出预览开始显示首批内容的等待时间低于 300 毫秒，一整句标准中文生成完毕的等待时间低于 800 毫秒。**本阈值不适用于用户在设置页面（见 002-lattice-dict-model-switch）主动选择的中配/高配模型**——用户选择更大参数规模模型即视为已知情地接受更长延迟以换取更高翻译质量（见 Clarifications "Session 2026-10-19"）。
- **SC-004**：在 macOS 与 Linux X11 环境下，用户确认输出预览后，标准中文结果无需任何额外手动操作即出现在此前聚焦的目标应用输入框内。
- **SC-005**：在不支持自动粘贴注入的环境（如 Linux Wayland）下，用户每一次确认操作之后，均能看到清晰的"已复制到剪贴板，请手动粘贴"提示，不存在静默失败或无提示的情况。
- **SC-006**：当本地模型缺失或推理/注入过程中出现异常时，浮窗在所有此类已识别场景下均保持可操作状态（不崩溃、不无响应），并向用户展示可理解的提示信息。
- **SC-007**：AI 生成的标准中文译写结果，在真实中英混杂草稿输入下，达到用户认为"可直接使用或仅需极少修改"的比例 MUST 不低于 60%（低于 docs/IME.md 背景材料中 70% 的建议性参考值，作为 MVP 阶段更宽松的初步验收及格线）。

## Assumptions

- MVP 面向单机本地离线使用场景，核心双流处理（快流词典纠错、慢流本地模型推理）均不依赖网络连接，这是 docs/IME.md 愿景中"本地优先"理念的直接延续。
- 目标用户是具备一定中英文读写能力、正在借助该工具进行英语主动输出练习的个人用户，与 docs/IME.md 愿景描述的使用人群一致。
- "此前获得系统焦点的目标应用"通过各平台标准的窗口焦点/前台应用机制识别；在该机制因系统权限未开启（如 macOS 未授予辅助功能权限）而不可用时，视为与"平台不支持自动粘贴注入"同一类降级路径处理，统一展示相同的"请手动粘贴"提示文案，不区分具体原因（见 FR-012）。
- 本次 MVP 的浮窗转换器是独立于系统输入法框架之外运行的常驻小工具，用户需要先手动启动该程序（或随系统启动），之后才能通过全局热键使用；是否需要开机自启动等运维细节不在本次范围内定义，视为内部实现细节。
- 学习提示气泡在 MVP 阶段的内容来源可直接复用本次慢流生成过程中产生的辅助信息（如有），不要求额外的独立生成流程或数据持久化。
- 浮窗转换器的核心交互仅针对单次、单句/单段草稿到标准中文的转换，不要求支持同时处理多个独立的转换会话。

## Out of Scope

- 真正的系统级输入法框架接入（Windows TSF、macOS IMKit、Linux Fcitx5），即让本工具出现在操作系统"输入法切换列表"中供用户像系统输入法一样直接切换使用；本次 MVP 仅以独立浮窗工具形式交付，系统级接入留待后续路线图。
- LoRA 等模型微调能力，以及噪声语料合成与训练管道；MVP 仅使用现成的开源量化模型配合提示词（prompt）工程，不训练或微调任何自有模型。
- 用户个人生词本、个性化学习记忆、学习进度统计等任何形式的个性化学习数据能力。
- 学习提示气泡的精细动画效果与"打字机式"自愈呈现；MVP 仅做纯文本静态展示。
- 在 Linux Wayland 等已知生态限制下实现无感、自动的文本注入；MVP 在此类环境下统一降级为"已复制到剪贴板，请手动粘贴"，不强行实现系统级无障碍注入权限绕过方案。
