# Quickstart: 粘贴降级与热键冲突反馈补完

**Spec**: [spec.md](./spec.md) ｜ **Plan**: [plan.md](./plan.md)

## 前置条件

```bash
export VCPKG_ROOT=$HOME/vcpkg
export PATH="/opt/homebrew/bin:$PATH"   # macOS；其余平台按既有 CMakePresets.json 配置
cmake --build build/macos --config Debug
cd build/macos && ctest -C Debug --output-on-failure
```

## 验证场景

### 场景一：目标窗口在浮窗唤起期间被切换后，确认时降级为手动粘贴提示（User Story 1，SC-001）

1. 实际运行 `Babel.app`，打开一个文本编辑器窗口作为粘贴目标，光标置于其中。
2. 按下全局热键唤起浮窗，输入一段中英拼音混杂草稿。
3. **在按下确认键之前**，手动切换到其他窗口（如浏览器）、或将原文本编辑器窗口最小化、或直接关闭它。
4. 切回浮窗，按下确认键（回车）。
5. **预期**：浮窗展示"已复制到剪贴板，请手动粘贴"提示（与 001 FR-012 文案完全相同），系统剪贴板中确实已写入标准中文译写结果；MUST NOT 观察到内容被模拟粘贴进入当前实际前台的无关窗口（如浏览器地址栏/搜索框出现了意外文本）。

### 场景二：目标窗口始终有效时行为无回归（SC-002）

1. 同场景一步骤 1-2，但**不要**切换/最小化/关闭原目标窗口，保持其持续在前台。
2. 按下确认键。
3. **预期**：行为与 001 既有流程完全一致（内容被正确模拟粘贴进目标窗口，浮窗正常关闭），不出现任何本特性引入的新提示或延迟。

### 场景三：热键注册失败时托盘图标与系统通知（User Story 2，SC-003）

1. 使用另一个工具/脚本预先占用默认全局热键组合（`Control+Option+Space` on macOS），制造注册冲突。
2. 启动 `Babel.app`。
3. **预期**：应用启动后短时间内，系统托盘/菜单栏出现一个新的应用图标（常驻），且弹出一条系统通知/提示，内容能让用户理解"全局热键当前不可用"这一事实（不要求字面匹配特定文案）。
4. 清除占用热键的其他工具，重启 `Babel.app`。
5. **预期**：热键正常注册成功，托盘图标仍然出现（常驻基础设施，与热键成功与否无关），但 MUST NOT 弹出"热键不可用"通知。

### 场景四：热键注册反复失败时不产生骚扰性重复提示（SC-004）

1. 延续场景三步骤 1-3（热键注册失败、已弹出一次通知）。
2. 在同一次应用运行期内，多次尝试按下该热键（观察无反应）。
3. **预期**：不会因为用户反复尝试按键而重复弹出多条通知；本场景下当前架构下 `registerHotkey()` 本身只在启动时调用一次（无运行期重试循环），该场景更多验证"用户反复按键本身不触发任何新通知"这一消极断言。

### 场景五：事后复述验证（SC-005，人工访谈类场景，非自动化测试范围）

1. 邀请测试参与者完整经历场景一与场景三。
2. 操作完成后访谈："刚才发生了什么？为什么会这样？"
3. **预期**：参与者能准确复述"目标窗口已切换，所以提示我手动粘贴"/"热键当前注册失败，所以弹了通知"这类因果关系，不出现"完全没有意识到异常发生"的报告。
